# 0.4.3 — guided physical setup and SciPy state reuse

This maintenance source edition makes layer stacks, interlayer connections,
passive circuit extraction and result review easier to follow. It retains the
recognizable desktop, existing physics, SciPy solvers, CLI and project formats.
Check [Releases](https://github.com/mmensing/electrothermal-layout-studio/releases)
for actual Windows downloads; this source version does not itself establish a
published binary or completion of its packaging gates.

## Follow the physical path

- Start from the layer inventory, choose material and role, and review bottom,
  top and thickness in the cross-section. Thin films remain visible through an
  explicit schematic view; that view is not a three-dimensional field solver.
- Create an electrical contact, via or thermal path deliberately from a selected
  layer pair. Review its exact geometric support and complete the shared draft
  before applying it. Projected overlap alone never creates connectivity.
- Select physical ports for a passive network, choose a reference convention,
  and inspect the same validated resistor network used for SPICE export.
  Selection or physical changes retire stale extraction; view changes preserve it.
- Read result headlines before detailed evidence. Working setup, selected result
  and active job have distinct context; setup and result cameras remain separate.
  Evidence controls use a compact disclosure, with guarded history and draft
  transitions retained.

Headline temperatures use 0.1 K resolution. Full fields, exports, residuals,
conservation and physical acceptance retain their precision and criteria.
Temperature differences of 0.01–0.1 K alone do not establish a meaningful
engineering problem or ranking.

## Reuse work within SciPy

Coupled iterations can reuse a converged electrical state only while its exact
inputs and temperature remain valid. A thermal boundary projection that changes
the temperature retires that carried state while retaining the Newton seed.
Cancellation, conservation and nonlinear acceptance remain unchanged.

The repeated, same-mesh 5 A E21 source comparison measured median complete-run
reductions of **18.6% at one CPU** and **21.7% at four CPUs** for this workload.
Four CPUs still do not promise a universal speedup: SciPy's sparse direct
factorization remains serial. These source measurements do not establish frozen
package performance or mesh verification. See [measured performance](../performance.md).

## Maintenance and compatibility

History-reader shutdown uses one total deadline and retains running workers until
safe cleanup. Negative regressions cover stale replies, cancellation, failed
reads, resource rejection, cache budgets and independent GUI fixture state.
CI retains bounded JUnit/timing evidence without reducing required checks.

Existing example projects, embedded layouts, historical build receipts and
solver-version identities remain intact. No new dependency, GPU runtime or
semiconductor model is introduced. The original source remains **MPL-2.0**;
the Windows profile uses the existing **GPL-3.0-only via MPL section 3.3** route,
with matching application/dependency source, notices and build information.
The 78 dependency source payloads remain unchanged; versioned source envelopes
and their catalog hashes identify the new release inputs.
