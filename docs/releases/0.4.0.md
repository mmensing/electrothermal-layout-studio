# 0.4.0 — an expanded example workbench

The library grows from 24 to **40 ready-to-open projects**, preserving E1–E24 and their
stable IDs. Start with [the GUI walkthroughs](../extended-examples.md): each new case
connects a design question, a configured calculation, a computed field and a
follow-up experiment. The [main gallery](../examples.md) links the complete catalog.

## What to explore

- **E25–E28:** series resistance, neck crowding, finite-contact transfer length and
  signed currents in a three-terminal network.
- **E29–E32:** an annular bus with a real opening, serial via banks, passive voltage
  taps and current sharing through resistive collection buses.
- **E33–E36:** a supported thermal bridge, insulated heater/sensor coupling,
  partial backside attachment and pulsed constriction cooling.
- **E37–E40:** a fully gated GaN coupon, independently driven GaN banks, a SiC
  on-state die with protected active islands and a three-metal package interposer.

**File → Ready-to-run examples** groups projects by purpose. Opening an example
prepares its geometry without starting a solve. The configured layer, quantity,
analysis type, connections, measurements and saved sweeps follow it through the
existing seven-stage workflow. Save a copy before experimenting. Generation and
CLI access remain available; no Python editing is needed for the walkthroughs.

## Numerical scope

The new references use existing sheet, contact/via, distributed-load and transient
models. Localized finite feeds retain routing resistance. Coupled references have
explicit thermal paths and a named backside reservoir; fixed-temperature electrical
coupons use an explicit temperature reference. They do not add artificial heating
to the Joule-heating calculation.

Selected exact nominal calculations on Windows 11, Python 3.12.14, eight physical
CPUs / 16 logical CPUs and 32 GB RAM, with four requested CPU threads:

| Project | Geometry and service | Computed maximum temperature |
| --- | --- | --- |
| E33 | 300 × 120 µm bridge layout; 0.3 mA | about 301.67 K |
| E36 | 600 × 240 µm pulsed neck; 1 A high level | about 302.27 K over the retained run |
| E38 | two 8 × 250 µm GaN banks; 0.25 A requested per bank | about 301.06 K |
| E39 | 1 × 1 mm SiC on-state die; 10 A | about 381.86 K |
| E40 | 1.8 × 1.6 mm interposer, 48 vias; 5 A | about 306.73 K |

These are synthetic examples, not device ratings or calibrated process predictions.
E28 prescribes its branch withdrawals; E38 independently prescribes bank service.
Neither demonstrates spontaneous equal sharing. E39's island sharing emerges from
the coupled sheet/load network. Its insulated gate drawing does not control the
fixed-on-state load. GaN's conductance floor is not a leakage prediction.

All 16 exact nominal projects were calculated with their configured loads and biases.
Validation checks delivered service, available scoped measurements, applicable
limits, electrical/thermal conservation, deterministic GDSII/OASIS generation,
export/reimport, embedded-layout reopening and complete typed result equality
through archive schemas 2 and 3. The pulse check includes all 21 retained frames.

**Converged does not mean mesh verified.** The bridge received an additional
coarse/fine check; its finer default removed a small temperature undershoot without
changing its thermal conditions. The new batch does not establish mesh-certified
routing rankings, high-field transistor behavior, switching or experimental
uncertainty. Existing engineering examples and analytical benchmarks remain
separate from the new teaching references.

## Reproduce and package

Run the complete exact-reference matrix deliberately:

```powershell
python scripts/verify_extended_examples.py --output .artifacts/extended-examples
python scripts/power_examples_desktop_acceptance.py --offscreen --catalog --solve --workflow E25 E33 E36 E39 --output .artifacts/desktop-extended-examples
```

The verifier starts a fresh process per example, limits each process tree to 3 GiB
and 300 seconds, and records actual phase timings, meshes, CPU settings and sampled
peak memory. These function checks can overlap other host activity and are not
portable performance benchmarks. The complete matrix runs in owner-requested/main
CI, while lightweight PR checks avoid automatically solving every large example in
every analysis mode.

Portable ETL, GDSII and OASIS assets are included in source and Windows resources.
The Python wheel contains the generators and runtime data; it does not duplicate
the external gallery. Archive schema 2 and eager history remain the defaults;
schema 3 and metadata-first history remain explicit options.

Original source remains MPL-2.0. A Windows candidate must pass the existing native
execution and third-party redistribution gates before public binary publication;
a version change or a successful local build does not clear them. Check the
[Releases page](https://github.com/mmensing/electrothermal-layout-studio/releases)
for actual published downloads and [the maintainer guide](../maintainer-guide.md)
for the owner-reviewed procedure.
