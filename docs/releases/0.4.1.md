# 0.4.1 — responsive projects and a clearer engineering workflow

Open projects and examples, inspect the inputs, and move from a computed map to
the evidence needed to assess it. This maintenance release retains the desktop
shell, solver models, forty reference IDs and existing project compatibility.

## Workflow improvements

- Default eager File Open, JSON/legacy fallback and consent/relink retries read
  and deserialize in owned workers. The working setup stays available until the
  draft/save/history guards accept the current request. Cancellation discards
  obsolete results; an in-flight native decode completes off-thread.
- Revealing Issues, Jobs or History retains the exact canvas center, zoom and
  selected field/range. Failed project opens identify the file operation and keep
  the current solved view available.
- Reopening the Model browser from either entry point selects its existing tab.
- New examples lead to **Mesh & Checks** without starting a solve. Compact example
  configuration stays above **Inputs to open** and **Model & use** tabs, with
  resource limits and Open/Cancel controls retained.
- **Results → Check mesh/time-step sensitivity…** opens the existing study for the
  applied physical setup. History stays read-only; changed setups and active jobs
  explain why verification is unavailable. A generated mesh is not verification.
- A shared versioned feature registry generates online/offline tables and the
  additive CLI capability catalog. Ordinary runs record build/dependency identity;
  About, `etlayout build-info`, archives and reports make that identity inspectable.
  Legacy results explicitly retain unavailable provenance.

The release also includes the reviewed post-0.4.0 engineering tools: hard
thermal limits, physical local mesh confidence, explicit thermal films and loss
deposition, whole-run transient peaks and same-support engineering quantities,
GUI-led scenarios and finite-contact TLM studies. See [engineering changes](0.4.x.md)
and the [feature catalog](../features.md).

## Performance and compatibility

On the same current E21 nominal **5 A**, 143,324-triangle mesh with 301,091 estimated DOFs, one
measured pair took **64.936 s with one CPU** and **72.422 s with four**. Four
assembly workers were confirmed and all 72 retained field arrays were identical.
The host had uncontrolled background load; this is evidence of concurrency, not
speedup or mesh convergence. See [performance](../performance.md) to reproduce.

Result-cache identity includes the implementation receipt. Physical hashes are
unchanged by display settings, execution preferences or provenance. Archive schema
2 and eager semantics remain defaults; schema 3 and metadata-first history remain
optional. Older hard-limit-free projects and old solver labels remain supported.
No physics model, transport calibration or solver acceptance tolerance is added.

## Validation and distribution

[Validation](../validation.md) records the comparable baseline and distinct source,
native and packaged scopes. Release publication requires the exact protected-main
CI, 27 actual native checks, seven extracted-folder checks, readable screenshots,
matching source and completed artifact/license/privacy review. A version change
or candidate build does not establish that those gates passed; consult the actual
[release](https://github.com/mmensing/electrothermal-layout-studio/releases).

The bounded native lifecycle diagnostic passed, but a broader local test order
reproduced the intermittent Qt/Shiboken garbage-collection fault. Its cause remains
unresolved; a passing diagnostic does not establish its absence. Clean-machine,
physical monitor-DPI, screen-reader and code-signing validation are not claimed.

Original source remains **MPL-2.0**. The combined Windows application follows the
existing **GPL-3.0-only via MPL section 3.3** route, preserving third-party/LGPL
grants. The source-built native profile and all 77 component source payloads are
unchanged; fresh versioned envelopes, notices, SBOM, source and hashes accompany
an approved release. No Microsoft runtime DLL or installer is bundled; install
the official supported x64 v14 prerequisite separately when needed. Always
extract the complete Windows folder and retain `_internal` beside the EXEs.
