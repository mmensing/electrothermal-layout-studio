# 0.4.2 — Qt lifetime stability and predictable CPU budgets

This maintenance source edition fixes a reproducible Qt/Shiboken reference
lifetime defect and makes native thread limits stable across a calculation.
It preserves the desktop design, SciPy solvers, project compatibility, forty
reference examples and scientific acceptance criteria.

## Desktop lifetime fix

The Qt binding retained pointers to Python objects while releasing those objects.
A finalizer could trigger garbage collection or re-enter a setter before the
stale pointers were removed. The dated Shiboken patch detaches retained references
before releasing them and completes replacements before old-object finalizers run.

The application uses **Shiboken 6.12.0+etlayout.1** with the original PySide6/Qt
6.12.0 bindings and public ABI. Four independent child-process regressions cover
GUI/worker collection and reentrant reference removal/replacement. They fail on
the original locked runtime and pass on the rebuilt runtime. Garbage collection
remains enabled; widgets are not retained indefinitely as a workaround.
See [the runtime guide](../qt-runtime.md) for source installation and limitations.

## CPU execution and release workflow

- Keep native numerical kernels at one thread for the complete owned run, while
  retaining the configurable assembly/study CPU budget (four by default).
  Restore the caller's limits after tasks finish. This removes repeated library
  scans and nested-team overhead around individual assembly batches.
- Retain SciPy's serial sparse direct factorization. Four assembly workers can
  execute without a fourfold whole-run improvement; the repeated E21 ranges
  overlap strongly. No universal speedup or new solver backend is claimed.
  [Measured results](../performance.md#stable-native-kernel-cap-repeated-source-comparison)
  preserve exact workload, implementation and scientific identities.
- Discover authenticated release drafts even before their Git tag exists.
  Verify the exact draft identity, notes and uploaded asset hashes by release ID;
  ambiguous or mismatched state remains an error. Publication is owner-controlled.

Owned Gmsh startup also preserves the caller's native PATH and PYTHONPATH.
Its upstream Windows initialization could truncate long values and break later
external-tool launches. The deliberately lone API startup switch prevents those
writes; ordinary and protected startup produced identical E1 mesh arrays on both
the locked stock and audited native runtimes. Borrowed Gmsh models remain owned
by their caller. No native Gmsh binary or numerical controls changed.

## Compatibility, source and validation

No physics model, material calibration, convergence threshold or accepted-service
criterion changes. Existing result versions and build receipts retain their
history. The 42 maintained ETL reference projects and embedded layouts retain
their original bytes and writer metadata.

The original **77 corresponding-source payloads** are retained byte-for-byte.
The Qt source part pairs its original PySide source archive with a modified
Shiboken source supplement containing the dated patch, modified C++, exact
recipe, notices and build evidence. Both archives are required together; only
the duplicate copy of the original source was omitted from the supplement. The application source remains **MPL-2.0**; the combined Windows
profile follows **GPL-3.0-only via MPL section 3.3**, preserving library grants.
No new sparse solver, GPU runtime or bundled Microsoft runtime is introduced.

The source version and passing runtime regressions do not establish a published
Windows artifact. Exact protected-main CI, complete native/extracted application
checks, readable screenshots and hash-bound source/SBOM/privacy/license review
remain release gates. Check [Releases](https://github.com/mmensing/electrothermal-layout-studio/releases)
for actual downloads. Clean-machine, physical monitor-DPI, screen-reader and
code-signing verification are not claimed. Very long custom Windows TEMP paths
can still exceed legacy path limits; use the normal short system temporary
directory for calculations and validation.
