Layout: start with a reproducible project

Choose File → Ready-to-run examples. E1 verifies DC resistance, E17 verifies thermal pulse response, E18 adds current pulses and temperature feedback, and E19 demonstrates delayed heating of an unpowered receiver through a shared substrate.

E20–E24 add millimeter RDL, long-finger and multi-bank GaN, and stripe/tiled SiC MOSFET on-state interconnect models. They open complete setups without running. Engineering presets can require minutes and several GiB; compact presets and additional feed/size combinations are available through etlayout examples --name E21 --preset compact. These are synthetic assumptions, not device ratings. See docs/power-examples.md for exact inputs, thermal paths, measured mesh checks and resource limits. Physical-port sweeps and pulse drives target the port rather than an owned landing terminal.

Import GDSII or OASIS and choose the intended cell. New masks start display-only; explicitly map the required masks to physical sheets in Layers & Materials. Unused annotation/fabrication masks need not be assigned. A via mask normally defines an interface rather than a separate metal sheet. Browse hierarchy through View → Hierarchy / layers / nets without changing physics; use the explicit Layout scope action to change the simulated cell/instance. Large branches reveal further instances through “Load next 100”.

A simulation domain changes physics: review clipped conducting paths and their boundary conditions. A view crop only frames the view; a measurement region scopes reporting. Pick the intended purpose, review the pending geometry, then Use selection to commit it. Overlapping-object candidates identify mask, layer and instance; hidden/non-pickable layers are excluded. Ctrl+click toggles a footprint. Polygon tools use click to add vertices, Enter or double-click to finish, and Escape to cancel the pending draft.

Edit layout above the canvas, Edit → Edit layout polygon vertices, or Ctrl+Shift+E opens vertex editing. Select an original polygon and drag its exterior or hole handles. Coordinates snap to the layout database grid; a focused handle moves one unit with arrows or ten with Shift+arrow. Apply vertices writes a verified project-owned OASIS copy, preserving the imported file and sibling hierarchy placements. Discard or Escape restores the applied polygon; Done leaves editing. Invalid geometry is red and cannot be applied. Boxes and edited path outlines become polygons. The inspector supports numeric exterior/hole coordinates, vertex insertion/deletion while retaining at least three vertices per ring, whole-polygon movement and configurable snapping in layout database units. Review affected contacts, interfaces, thermal supports, measurements and protected regions before applying. The shared Apply/Discard/Stay, Undo/Redo and immutable imported-file safeguards apply to these operations; this is polygon editing rather than general CAD construction.

Leaving a pending vertex draft offers Apply, Discard or Stay, including before saving or historical inspection. Undo/Redo restores applied revisions. Layout edits invalidate the working mesh and fields while preserving recorded runs. Contacts, domains, measurements and routing rules retain their definitions, so validate their support and connectivity again with F6. Save embeds the edited layout in the portable project. Historical inspection and active calculation/edit workers block physical edits. Large hierarchies may require selecting a smaller instance; see docs/layout-editor.md for limits and transform handling.

Setup: define the physical model

  1. Open Layers & Materials. Assign geometry, project material, thickness, bottom elevation and role to each sheet. Complete model tables and Materials and library remain under Model.
  2. Define electrical and thermal interfaces over the real overlap or via footprint. Projected overlap alone does not connect layers.
  3. In Contacts & Connections, choose external port, interlayer contact, passive probe, floating electrode, gate or boundary terminal before placing geometry. A port may own several local landing footprints. Positive current enters the device. Total current uses A; distributed current density uses A/m². On an edge the density is integrated over edge length × sheet thickness.
  4. Operating Conditions groups electrical inputs, port drives, thermal boundaries, heat sources and initial conditions. Supported thermal conditions include fixed temperature, ambient conductance/resistance, insulation and prescribed total W or W/m² heating. A steady thermal problem needs a heat-removal path; transient adiabatic heating can store energy without a sink.
  5. Mesh & Checks and Simulation → Numerical settings expose supported mesh sizes, solver tolerances, engineering warning thresholds, presets and notes. Numeric forms accept engineering units, for example 20 mV, 2 µm and 25 µs.

Common fields appear in the inspector, with advanced settings still reachable. Apply commits to the shared project and undo history; Cancel discards the draft. Leaving a dirty inspector offers Apply, Discard or Stay. Model tables and the embedded study workspace use the same document.

Layers & Materials → Technology templates… saves/loads portable .etltech.json physical mappings. Choose which layers to import and map each required template mask to an actual source mask, then Preview. The proposal shows file hash, source project, material provenance and added objects; Apply requires confirmation. Existing layers/materials stay intact, and unused source masks stay display-only. Templates copy physical layer models/material snapshots and declared contacts, not project terminal drives, thermal boundaries, heat sources or waveforms. Project-specific gate-terminal bindings are omitted explicitly; review gate conditions after applying. Template provenance is retained in project notes, and the complete application is undoable. Mesh/solver presets remain a separate task.

Solve: choose physics and time operation

The persistent Analysis selector offers the five supported combinations below. Switching preserves dormant ports, thermal settings and waveforms, updates prerequisites and does not run automatically.

Supported choices in the header Analysis selector
ModeSteadyTransient
ElectricalDC conduction at the configured temperatureUnavailable: no electrical storage equation
ThermalHeat flow from prescribed sourcesHeat storage, heating and cooling
ElectrothermalCoupled current, heating and temperatureThermal dynamics with quasi-static electrical feedback

In Thermal mode, Include electrical heating calculates losses at the reference temperature; it recalculates them for each transient drive but does not feed warming back into resistance. Electrothermal mode includes electrical heating with temperature feedback automatically.

F6 validates geometry and connectivity, including effective pulse/PWL drives. The Issues drawer provides Locate/Fix actions linked to the relevant object or setup. F7 generates a mesh. F5 runs the selected operation; Shift+F5 cancels. A warning is not automatically blocking, and acknowledging a message cannot repair physics. Read residuals, current/energy balance and completion diagnostics before interpreting fields. Setup freshness, solve convergence and mesh verification remain separate states.

CPU settings and background calculation

Edit → Execution settings… contains Total CPU thread budget and Parallel study worker limit. Both default to four, capped at the available logical CPU count; workers cannot exceed the total budget. Larger electrical and thermal assemblies use bounded worker threads. Supported native numerical libraries and Gmsh share that budget. Independent sweep, design, mesh and time-step study points divide the budget across separate processes. For example, four CPUs and two active workers allow two assembly/native threads per worker. More simultaneous points also need more memory.

Preparation and simulation run in the background so the desktop controls remain available. Cancel stops an active calculation and its study workers. Small assembly batches, geometry work and SuperLU sparse factorization remain serial, so CPU activity varies by phase. Results record actual assembly batches, worker IDs and CPU/wall time separately from the configured budget. More CPUs do not guarantee a faster solve. Preferences apply to future jobs, are saved on this computer and recorded separately from project physics. GPU acceleration is not included. The CLI reports available CPUs and native thread-control support with etlayout.exe capabilities.

Pulse settings: timing, waveforms and advanced controls

Select a transient analysis in the header and open Simulation → Time and load settings, also reachable from Operating Conditions. Timing contains stop time, maximum step, saved-field interval and initialization. Waveforms contains readable source names, constant/pulse controls, a piecewise-linear time/value table and a preview. Advanced contains storage budgets, peak retention, Thermal capacity and optional periodic convergence.

Thermal capacity offers consistent or lumped discretization. Consistent P1 capacity is the default and may undershoot a physical temperature bound under localized short pulses. Lumped capacity reduces this risk, but adverse mesh or interface coefficients can still defeat monotonicity. Read the diagnostic and check mesh/time refinement; energy balance alone does not prove physical bounds.

A waveform replaces the selected static source value. Undriven values remain constant. Pulse width means the high plateau; rise + plateau + fall must not exceed the period. A zero period means one pulse. Thermal dynamics do not model electrical capacitance, inductance or switching overshoot.

Maximum step controls integration accuracy. Pulse edges, waveform knots and saved output times split integration steps. Hold the output interval fixed during a time-step refinement study. Initial fields at t=0 use the right-hand drive; subsequent fields at an ideal edge use the incoming interval's left-hand drive. The selected-time label and export metadata identify this convention.

Initialize uniformly, solve a steady initial bias, or use Simulation → Start transient from saved state. Resume saved transient continues from its accepted time to an absolute stop time and retains cumulative energy accounting. Saved fields must be compatible with the current geometry, mesh and thermal model; incompatible states are rejected.

Periodic convergence is optional and uses repeated temperature agreement at a common phase of equal-period pulse drives. It reports an early-stop reason and actual end time. It does not establish time-step accuracy; compare refined runs separately.

Inspect: keep spatial and temporal scope explicit

Choose layer, field and support in Results. Each field maps one layer's solved support. Regions can select islands or named terminal, source, interface and boundary footprints. The selection controls maps, vectors, mesh, probes, profiles, statistics and displayed-field exports. Holes and unavailable fields stay unpainted. Isolate layer hides unrelated geometry; turn it off for context. Fit layer frames the active field.

For transient results, use the saved-time controls or enter a time to choose the nearest retained field. Peak selects the retained whole-run temperature peak when peak retention is enabled. The spatial Hotspot command locates the maximum of the currently displayed quantity and region. Whole-run warnings remain visible while inspecting cooler frames.

The retained results controls include time history with Whole device, Selected layer / region and Map probe scopes. Whole-device scalar history includes every accepted step. Local traces are derived from retained fields: sparse output can miss a local peak. Click a trace to select its nearest retained map frame. Exporting a scoped trace records that selection.

Results display settings retain Appearance and Compare controls. Choose Teal, Viridis, Magma, Cividis, Coolwarm or Grayscale. Manual range accepts unit-aware limits; Auto uses finite support. Across-time limits retain a common scale across snapshots. Log scale needs positive values. Smooth interpolates nodal fields; vectors show normalized directions. Color clipping never changes numerical values.

Compare layers synchronizes field, time, palette, scale and optional physical pan/zoom; each panel can select a layer and region. Run comparisons expose linked nearest-time or independent time selections and record both actual source times, including when saved grids differ. Difference fields retain finite common support. A comparison's time match is a sampling choice, not time interpolation.

Probe a point, draw line profiles or draw a cross-section through physical layer occupancy. Profiles preserve gaps. Branch current integrates a directed cut; positive flux points toward its left normal. Run history retains configurations and opens a marked read-only inspection context. Return to current project restores editing.

Probing reports in the status bar and updates the time trace without opening another panel. Timeline dragging coalesces updates and reuses cached history ranges; the first across-time range calculation can still take time for a large history.

Studies: check discretization and controlled changes

Mesh & Checks → Suggest local refinement prepares reviewable contact-transfer, gated-channel, narrow-island and physically averaged hotspot sizing. Preview and Cancel preserve the working setup; Apply is undoable. A bounded local study uses two to four decreasing factors, keeps global sizing and physical averaging lengths fixed, and compares resistance, delivered current, like-sized device-group sharing and regularized hotspots. Levels run serially with the selected CPU thread budget. Element/DOF limits remain enforced by the mesher; the additional numerical-memory screen excludes process baselines and does not guarantee peak RSS. Successive changes are empirical mesh sensitivity, not an automatic verified badge. The CLI shares this workflow through mesh-plan and refine --local-plan.

Studies offers parameter sweep, mesh and time-step convergence, project comparison, routing and optimization, and saved study results. Time refinement keeps output interval fixed and reports peak temperature, peak time, generated/exported/stored energy, energy imbalance and changes between steps. Periodic early stopping is disabled for the study so runs share an end time.

Parameter sweeps record requested and applied values. Sweep a waveform amplitude through its waveform path, not the static source it overrides. Ideal corner current peaks are mesh sensitive; compare integral quantities and physical profiles as well.

Mesh and time refinement compare the same requested duration with periodic early stopping disabled. Failed study points retain a visible status and do not connect successful curve segments. Saved-state studies reuse the source mesh; changing its geometry or mesh requires uniform or steady initialization. Source-bound presets require their original state or an explicit initialization change.

Power interconnects and constrained routing

Studies → Routing & optimization embeds the power workspace in the same document, grouped into Setup, Analysis, Routing and Experiments. Define physical ports and local landing footprints, scoped measurements, fixed device groups, geometry rules and bounded recipes. Typed recipe and scenario controls cover supported inputs; advanced overrides remain available. Calculations run through the existing background worker. CPU preferences are in Edit → Execution settings.

Analysis → Reanalyze retained fields validates source-physics compatibility and computes a new report from a copy of the selected result without a new field solve. The report records original field and current reporting configuration hashes. Measurement-specific references override the current project reference; removing a thermal reference requires a single physical reservoir temperature or a new explicit/named reference. Original solver metrics and history remain unchanged.

Inspect individual contact/via loading, named thermal reservoirs and the disjoint loss budget. Result views show sheet current in mA/µm and volumetric or contact-normal current density in mA/µm²; these remain distinct quantities. For example, 10¹⁰ A/m² displays as 10 mA/µm². Electric field uses V/µm, heat density W/mm² and temperature gradient K/µm. Manual ranges use the displayed unit. Solver data, input settings and numerical CSV/JSON/VTU exports retain SI units; figure metadata records both ranges. Absolute temperature and temperature rise remain K. Select fixed physical averaging windows when comparing hotspots. Empty or stale selections are unavailable. Passive probes observe; floating electrodes impose an equipotential and can redistribute current.

Routing generates a new GDS/OASIS source copy and verifies the reimported geometry. Protected masks and external ROI geometry remain intact; a selected reused instance is cloned. Physical vias validate stack height, landing enclosure and dielectric replacement. Effective couplings preserve their declared assumptions.

Experiments compare the same current/service requirement across all scenarios, preserve fixed active geometry and report failed candidates explicitly. Coarse feasibility is provisional. Baseline and finalists need mesh refinement and exported-file simulation before a verified improvement can be claimed. Mesh changes estimate uncertainty; they are not rigorous error bounds. Existing transient studies remain separate from steady routing optimization. See docs/POWER_ROUTING.md in the application folder for examples, CLI commands, migration and model limits.

Measurement support retains exact clips through nested device groups. Exceedance uses a dimensional threshold and an independent max_exceedance_fraction; legacy overloaded limits require explicit migration. Passive SPICE export retains weak connections and rejects unestablished per-port fidelity. Via width and transition-wide pitch/spacing use actual geometry. See docs/scientific-acceptance.md.

Save, export and recover

Results → Export task groups map, displayed field/support, original numerical result, report and selected-run project archive destinations. Check the stated run, time and support before exporting. A selected-run archive contains that run's original physical configuration and fields; File → Save project retains the working setup, embedded layout and run history. A transient archive includes scalar history, snapshots and initialization/continuation provenance. Export original numerical results includes every original layer and complete history. Export displayed field / region records the selected snapshot and support. Time-history CSV/JSON use SI values; plot axes use labeled engineering units.

Physical edits invalidate the current result while keeping recorded runs. Display changes and notes preserve fields. Recovery runs every minute when changes are unsaved. A recovery warning identifies write failures. View can save, restore and reset dock layouts or select Dark theme. Time-history plots follow the theme; other scientific plots retain white canvases.

The run-history panel shows estimated retained memory and allows removing selected runs. Saves check the complete expanded archive budget before replacing an existing file. A rejected save preserves the previous archive. Remove unneeded saved runs, or rerun with a longer saved-field interval and remove the superseded larger run before saving. Changing the interval affects future solves; it does not thin fields already retained in a result. Exported transient histories include the initial-state source, segment time interval, cumulative-energy scope, peak scope and stop reason, including in the CSV metadata sidecar.

Physical scope and interpretation

The model uses thickness-averaged 2.5D sheets with declared vertical transfer. Density and specific heat supply thermal mass; interfaces have no separate heat capacity. Through-thickness transient diffusion, electrical RLC dynamics, phase change and adaptive time stepping are not modeled. Representative materials require calibration. The effective HEMT model excludes drift-diffusion, trapping, breakdown and field-plate electrostatics. Engineering thresholds are warnings, not failure predictions.
